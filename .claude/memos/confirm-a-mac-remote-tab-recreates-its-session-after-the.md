# Confirm a Mac remote tab recreates its session after the Windows machine reboots

Since 3df2807 (2026-10-13) a reconnecting Mac tab creates a missing session, now limited to one that did not end cleanly: mac/attach.sh reconnects by running cc-session.sh in `resume` mode (a pick runs `start`), so a tab whose session is gone should start it again, resuming that directory's conversation, with no prompt. Nothing has observed it yet. Killing the tmux session while a tab is attached does NOT test it: tmux exits the client with 0 and attach.sh's case 0 stops the tab by design. The path only runs when the transport drops AND the session is gone, which is what a Windows reboot does. Test: leave a remote tab open on the Mac, reboot the Windows machine, and wait for the tab's reconnect (up to five minutes of backoff). Expect the tab to come back attached to a fresh claude.exe that resumed the conversation, not stopped on 'not connected' or 'refused'. Without a reboot: turn the Mac's Wi-Fi off while it is awake and wait until the tab prints 'attach: lost the connection' (the ssh ServerAlive deadline ends it with 255 after about a minute), then on Windows run `tmux kill-session` on the tab's cc-* session, and turn Wi-Fi back on; kill-session writes no ended marker, so the next resume recreates it. Sleeping the Mac does not cut its ssh in time: the README records those connections surviving one to six hours of sleep, so a session killed then still reaches the Mac as tmux's exit 0 and the tab closes by design. Do not use `tmux kill-server`: it also kills the holder's `_holder` session, so every check exits 4 and the tab loops on 'the holder is down' without reaching the recreate path. A tab that closes has three possible causes, and in agterm none of them can be read off the tab, because a 0 or a 5 closes it in the same instant the lines are printed; run attach.sh outside agterm to read them, or look in WSL on the Windows machine. One is the agent exiting 0 at logoff (the unmeasured EPIPE/EIO path in .claude/memory/remote-tabs-always-recreate.md), which writes the ended marker so the resume check exits 5 and prints 'cc-session: <name> was ended on purpose'; the marker stays at `~/.local/state/claude-remote-session/ended/<name>` in WSL until the next create, so finding it there after the close identifies this cause. The second: if cc-session.sh's attach-after-create races or fails, the tab closes as if the session had ended (the Windows sshd turns every exit of the -t attach into 0, so no 1 ever shows), and no marker is left. The third is the no-reboot recipe run out of order: a session killed before the tab printed 'lost the connection' closes the tab through tmux's exit 0, again with no marker.
