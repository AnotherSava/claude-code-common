When replying to someone who filed an issue, ask only what they alone can answer. Don't ask them to settle scope the maintainer owns (which emulators are supported: "GBE first, others on request"), or for figures only we would use (how many games they track, which was only for sizing performance). Don't turn the reply into a questionnaire; close with an open "feedback and questions welcome". Don't advertise a capability the typical user can't use (a window that "stays open while you play" when most play full screen on one display). If something is worth doing whatever they answer (global rarity), plan it and say so rather than asking whether they want it.

**Why:** the user cut three of five drafted questions from an achievement-overlay issue reply on 2026-09-30 for exactly these reasons.

**How to apply:** before showing a draft reply, test each question: would the answer change what gets built, and could only the reporter give it? Drop the rest. Pairs with [[feedback_issue_reply_feature_first]].
