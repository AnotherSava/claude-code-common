When documented knowledge exists, circulate the document rather than a hand-typed restatement of it — and when you *receive* a restatement about something that has a document, read the document before acting on it.

**Why:** a restatement can only lose fidelity, and it does so invisibly, because it arrives carrying the same authority as the thing it paraphrases. Nothing about a confidently-typed command looks lossy. A lead sent three sessions a transcrypt verification command with one character hard-coded that actually varies per encryption; the learning it was paraphrasing already said so and tabulated every possible value. I then built an assertion from the message rather than from the learning — which was on my own disk, in a directory I had listed minutes earlier — and it announced "NO — PLAINTEXT, STOP" on a correctly encrypted blob. A confident false alarm, instructing a `git reset` and a fix to something that was never broken. The error propagated one step further than it was sent, and the cheapest place to stop it was the receiving end.

**How to apply:** when you would paste a procedure into a message, paste the path to the document instead, or quote it and name the source so the reader can check it. When a procedure arrives from another agent and touches something with a learning, open the learning first — above all before encoding it into a test or an assertion, where a wrong check produces confident false results rather than an obvious failure.
