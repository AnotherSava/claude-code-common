When you append a correction, a closure, or a "verified since" note to a living document, **re-read the entry from its first word before saving.** The append is where your attention is. The opening sentence is where the reader's is, and it is the one that sounds authoritative.

**Why:** four instances in two days, all self-inflicted, across two different artifacts. In a skill file, "Leave it unset. The host supplies it." was added to a bullet that still opened "Set it on any box that hosts more than one project" — anyone following the skill top-down would have done the opposite of what it now intended. In a memos file, three entries contradicted their own closing lines: one opened "One residue left… and it is not landlord's" after both residues were closed; one said a skill "still hands out that exact form" after it had been removed; one opened "the fix is committed but not yet on every machine" directly above a line stating it had reached every machine. Every one was written by appending something true to a lead that had gone false without being touched.

**Finding one of these later: do not assume it took two writers.** Where more than one agent edits the same files, "our edits collided" is the seductive explanation and it is usually wrong — a contradiction is far more often *one* commit that added a corrected claim beside the stale one, which is exactly the failure above. Seen 2026-09-03: a project memory said scheduling was "still unbuilt on `air`" twelve lines above "now built on both". I reported it to a peer as its edit and mine both landing; the peer disproved it — `git show <commit>:<file>` already held both clauses, and `git log -S` on each showed the *same* commit introduced the second without removing the first. Mine, and its message was "record that scheduling and liveness are built on both machines". **Run `git log -S '<clause>' -- <file>` on each half before naming a cause.** One command, and the wrong diagnosis sends the fix hunting a coordination problem that does not exist — which is also the more comfortable answer, since a collision makes the contradiction nobody's fault.

**How to apply:** the trigger is the append itself, not a later review pass — nobody schedules a review of a sentence they believe is fine. Before saving, read the whole entry top-down once and ask whether the first sentence still makes the claim the last one supports; if not, rewrite the lead rather than trusting the reader to reach the bottom. Long append-grown entries are the risky shape, because the correction is always at the end and the reader stops at the beginning — which is also an argument for rewriting an entry in place instead of accreting to it.
