The user flagged a memory that opened "Oleg reads slowly" as "a bit too personal to put into memory," so I reframed it as a preference (prefers generous notification timing) and dropped "slow_reader" from the file slug.

**Why:** Committed memory is shared / version-controlled and outlives the moment; a personal-trait characterization reads as a value judgment and is uncomfortable to have recorded, whereas the actionable content is the *preference or behavior*, not the trait.

**How to apply:** When writing memory (its body, description, filename, and index line), describe what the user *prefers or does* ("prefers generous timing on delays") rather than what they *are* ("is a slow reader"). Keep personal characterizations out of the slug too, since it's visible in the repo.
