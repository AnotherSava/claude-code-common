# Links handed to the user go over the tailnet

**Anything handed to the user to open gets a tailnet URL** — an HTML page (contact sheet, comparison, generated report), an image, a PDF, a running dev server or docs preview — so the link opens on every machine in the user's tailnet, the phone included. Never a `file:///` link, which opens on only one machine because the two share no filesystem path, and never `localhost` or `127.0.0.1`, which names a different machine on every device that clicks it. A file gets published with `python ~/.claude/skills/shared/tailnet_publish.py publish <file>` (`python3` on macOS), which prints a URL it has already fetched back; hand that one over as a Markdown link. A server gets fronted with `tailnet_publish.py publish-port <front> --target <the port it listens on>`, which prints its URL once a request through it has been answered; hand over that one with the path the work is about appended. Choosing the front port and why it must differ from the server's own: `~/.claude/learnings/tailscale-serve-port-ownership.md`. **Never write a `.ts.net` host yourself, and do not keep one from earlier in the session** — the tailnet segment is a random id, so a hostname assembled from the pattern is unverifiable and wrong: a host built from the machine name and a remembered id went out in place of the real one, resolved nowhere, and had the shape of a working link. Running the helper is the only way to learn the host, and it is cheap enough that recalling one is never worth it. The one server that keeps `localhost` is one whose origin is pinned there — an API key, an OAuth redirect, a CORS allowlist restricted to `http://localhost:<port>` — and the handover says so. **Where a tool publishes its own output and prints a URL, hand over that URL verbatim**; when publishing fails, the helper says why on stderr, and the `file:///` link goes out with that reason beside it rather than as a silent substitute. A path the user is meant to read or edit in their editor — a `file_path:line` reference — is not this; a link is something to open, and this rule is about the things meant to be opened.
