# Conventions

A convention written in `claude/CLAUDE.md` is a claim about every repo on this machine, so changing one leaves the rest in the old shape: the one such change made by hand so far missed a repo entirely and left five more holding the work uncommitted. So a change that an already-conforming repo must **do something** about ships as a numbered migration — one folder under `claude/conventions/versions/`, its number in its name, carrying prose an agent follows and the evidence that settles when it does not apply — committed alongside the change that caused it. Each repo records one integer in a committed `.claude/conventions`, how far that sequence has run there — plus, in a fork (`origin` the user's, `upstream` someone else's), a `decline` line for each version marked `optional: forks` it chose not to take on, while a clone of someone else's project adopts nothing; a SessionStart hook prints the gap once per session, and `/adopt`, run in the repo that is behind by the session that owns it, walks the pending versions one at a time and commits the number through `shared/commit.py`; a repo cloned on two machines is walked on one of them only, and the other clone takes that commit through `/pull`. What must hold *continuously* is never a version but a **rule** under `claude/conventions/rules/`, run by `claude/conventions/check.py` from that repo's commit gate — every rule its number entitles it to, at every commit, with a rule that could not look reported as unmeasured rather than as a pass. Beside those sits the smaller class in `claude/conventions/universal/`, gated by no number and so running in every repo whose gate calls the checker, with no adoption in between: what belongs there is a property no migration could settle for good because it is not about the repo alone and whose violation nothing else would report, and each one names the command that repairs what it found. Anything a repo can adopt stays a version. What can never carry a version at all is enumerated in `claude/conventions/not-versioned.md`, so "current" means every versionable convention has been decided rather than every rule in `claude/CLAUDE.md` being satisfied.

**Adopting is the business of the repo's own session.** When a session notices that some other repo is behind on its conventions — in a checker run, a status table, a scan across repos — it does not offer to message that repo's session about it and does not offer to memo the adoption. The one exception is work this session needs that the missing version blocks; then say what is blocked and route it.

The full guide, with how a version is written and adopted: `docs/convention-versions.md`.
